# 外贸智慧协同（Trade-Pro）· 平台全景介绍

> **文档用途**：给 AI 大模型 / 顾问 / 投资人分析师阅读，用于理解产品全貌、设计理念、功能地图与相对主流获客工具的差异。  
> **产品对外名称**：外贸智慧协同  
> **内部工程名**：Trade-Pro  
> **阅读约定**：下文「前台」指业务员可见界面；「管理后台」指 admin 配置与组织权限。前台文案刻意不暴露供应商/模型商品名。  
> **更新日期**：2026-11

---

## 1. 一句话定位

**外贸智慧协同**是面向出口团队（尤其玩具/礼品等产业带工厂外贸部）的 **「找客 → 背调 → 匹配 → 触达 → CRM 跟进 → 设计出样」一体化操作系统**，而不是单一的「邮箱查找插件」或「冷邮件发送器」。

核心主张：用 **可核对的公司/产品/渠道证据** 驱动开发动作，替代「人海搜名单 + 感觉写邮件 + 工具彼此不通」。

---

## 2. 设计理念（必须理解）

### 2.1 三条原则

1. **任务流先于功能堆砌**  
   指挥舱 / 今日看板引导「下一步该做什么」；模块按外贸真实阶段编排，而不是按技术模块罗列。

2. **证据先于文案**  
   开发信、匹配结论、适市建议应挂到：官网/背调画像、品类与价带、决策人线索、（规划中）货架与进口行为等可核对信息。禁止把未校验的邮箱/臆造联系人当正式结果入库。

3. **垂直场景优先**  
   优先服务出口业务员日常：批量背调、CRM、产品匹配、包装/平面/3D 出样、邮件与社媒触达。通用销售情报库（Apollo 式）不是主战场；平台强调 **自有作业队列 + CRM + 设计闭环**。

### 2.2 组织与权限模型

| 角色 | 能力边界 |
|------|----------|
| 系统管理员 (admin) | 全功能；可进业务工作台；可开启本机「挂机执行」；配置密钥与数据接入 |
| 总管 (director) | 跨部门浏览业务数据 |
| 部门主管 (manager) | 本部门数据；可管下属权限 |
| 业务员 (user) | 仅本人创建/归属数据；决策人邮箱对员工脱敏为 `*` |

云端数据按 **公司工作区** 共享合并；界面再按归属过滤。业务员本机不自动跑重任务；admin 挂机端可白天轻量补全、夜间重补全。

### 2.3 前台保密原则（实现约束）

面向业务员的文案 **不出现**：内部检索顺序、缓存键、降级链、大模型/供应商商品名。  
管理后台可保留供应商名以便配置。

## 3. 信息架构（五板块 + 指挥舱）

导航为圆形侧栏板块，再进子模块：

| 板块 | 英文 | 模块 |
|------|------|------|
| 指挥舱 | Hub | 今日看板（任务流 / 资讯 / 汇率等） |
| 商机 | Opportunity | 客户搜索、背景调查、产品分析、决策人挖掘、同类推荐、产品匹配 |
| 产品 | Product | 产品库、报价/选品单、平面设计、3D 设计、AI 视频、包装设计、产品匹配；3D 打印（占位） |
| 宣发 | Promote | 网站设计开发、发文素材加工 |
| 联动 | Connect | 开发策略、客户管理 CRM、邮件营销、联系工具、营销工具（背调作业） |
| 生态 | Ecosystem | 配件/周边/认证/验厂/交付（多为 Coming Soon 占位） |

**产品匹配**在「商机」与「产品」双入口（客户适市 vs 定价/SKU 视角）。

## 4. 功能地图（按外贸作业链）

### 4.1 获客与名单

- **客户搜索**：按产品关键词、国家、行业、客户类型搜索潜在买家；结果可归档、可批量进背调/CRM。  
- **获客公式 / 营销工具**：预设行业获客剧本，一键进入平台内搜索（不跳外网杂站）。  
- **Excel 批量背调**：下载名录模板 → 上传 → 与 CRM/历史去重分类 → 经济/详细模式入队；大批量可夜间挂机续跑。  
- **同类推荐**：从已背调公司扩展相似目标。

### 4.2 背调与情报

- **背景调查**：公司官网/公开信息结构化报告（公司概况、产品、渠道线索等）。  
- **产品分析**：品类、价格带、设计信号等（支撑匹配与出样）。  
- **决策人挖掘**：联系人姓名/职位/领英等；**邮箱须经专业校验链路后才写入**（规则/模型只生成候选）。  
- **批量队列（营销工具 · 背调作业）**：待处理/进行中/完成；可继续待处理、同步云端、导出。  
- **补全任务**：设计信号补全、背调补全（产品/市场/匹配）、品类深挖、夜间静默补缺口等，左下角任务条看进度。

### 4.3 匹配与 CRM

- **产品匹配**：国家/客户与产品库、背调画像对齐；生成匹配理由与跟进建议。  
- **客户管理 CRM**：正式客户库、标签、跟进、批量补全入口；与背调历史、作业队列对齐展示。  
- **记录中心**：历史搜索与背调档案（研究档案 ≠ 正式客户数）。

### 4.4 触达

- **开发策略**：基于背调上下文的策略对话与开发信草稿。  
- **邮件营销**：开发信/群发相关能力（与 CRM 客户关联）。  
- **联系工具**：WhatsApp / Skype / 微信等官方入口联动（非伪造登录）。  
- **发文素材**：社媒文案加工。  
- **网站设计开发**：对话/模板建站方向能力。

### 4.5 产品设计与报价

- **产品库**：SKU 主数据；可与管理后台货源同步（配置后）。  
- **报价 / 选品单**：从产品库生成报价与选品草稿。  
- **平面设计 / 包装设计 / 3D 设计 / AI 视频**：出样与视觉资产；3D 支持本机素材库回挂、原模/分件预览等。

### 4.6 管理与运行

- **Admin 仪表盘**：API/模型路由、数据接入、组织权限、用户、知识库、看板预览。  
- **挂机执行**：admin 进业务台确认后，本机按日程跑轻量/重补全与队列（需保持页面打开、电脑不休眠）。  
- **云同步**：CRM / 背调历史 / 产品画像 / 作业队列 本机 ↔ 云端合并；增量上传；大历史分页防超时。

## 5. 关键数据对象（概念模型）

| 对象 | 含义 |
|------|------|
| Discovery 结果 | 搜索命中的潜在公司（会话/归档） |
| Automation 队列任务 | 背调作业（pending/analyzing/completed/failed） |
| HistoryItem | 背调报告存档 |
| Client (CRM) | 正式客户；含归属 ownerUsername / departmentId |
| DecisionMaker | 决策人；邮箱字段需校验来源 |
| ProductProfile / Catalog | 产品画像与 SKU |
| 补全队列 Job | 设计信号、背调补全、品类深挖、邮箱深挖等 |

**对齐口径**：营销工具里「正式客户数」必须以 CRM 为准；「队列任务数」可因同公司多任务大于客户数；「仅 CRM 补录」表示队列里没有、从 CRM 补进列表的行。

## 6. 与市场主流获客/销售工具的区别

### 6.1 主流工具通常卖什么

| 类型 | 代表能力 | 用户付钱买的是什么 |
|------|----------|-------------------|
| 邮箱查找 / Chrome 插件 | 扫当前页 mailto、按域名查库 | 积分 + 验证 |
| 销售情报大库 | 海量联系人/公司库 + 筛选 | 席位 + 积分；库会过期 |
| 冷邮件 Sequencer | 多域名发信、暖机、序列 | 发送基础设施 |
| 单点设计工具 | 出图/出视频 | 按次或订阅 |
| 通用 CRM | 跟进管道 | 席位 |

这些工具 **彼此割裂**：找邮箱的不管背调，发信的不管产品匹配，设计的不管 CRM。

### 6.2 本平台相对优势（给模型的对比结论）

| 维度 | 主流获客工具 | 外贸智慧协同 |
|------|--------------|--------------|
| 作业单元 | 「一条联系人/一个邮箱」 | 「一家目标公司的作业」：搜索→背调→决策人→匹配→触达→CRM |
| 数据主权 | 租用对方大库 | **自有 CRM + 作业队列 + 背调档案**；云端公司工作区共享 |
| 邮箱策略 | 查到即用 | **校验后入库**；员工侧脱敏 |
| 批量 | CSV 进 Sequencer | Excel 批量背调 + 去重分类 + 挂机/夜间续跑 |
| 产品侧 | 通常没有 | 产品库、匹配、平面/3D/包装/视频出样闭环 |
| 组织 | 个人席位为主 | 部门归属、主管可见范围、admin 挂机端 |
| 中国产业带场景 | 通用全球 SaaS | 面向出口业务员日常与工厂外贸部协同 |
| 插件扫页 | 常是主产品 | 可增强，但不是全部价值；价值在闭环 |

### 6.3 诚实边界（避免模型过度承诺）

- **不能**宣称「免费替代全球联系人库」：专业邮箱验证与外部情报仍可能消耗配置的接口额度。  
- **不能**宣称已完整替代验厂/认证/货代 ERP：生态板块多为占位。  
- **跨端同步**依赖云端配置与网络；超大背调历史需分页/续传，不是「一点即秒同步完九千条」。  
- Chrome「打开网页抠邮箱」是增强项，主能力仍是域名作业流 + 校验入库。

## 7. 典型用户旅程（演示/培训可用）

1. 登录 →（admin）进业务工作台 → 确认是否本机挂机。  
2. 客户搜索或 Excel 批量导入 → 任务进入背调作业队列。  
3. 打开完成报告：公司背调 / 产品分析 / 决策人。  
4. 需要时点「搜索决策人邮箱」（校验链路）。  
5. 产品匹配 / 写入 CRM。  
6. 开发策略生成开发信；或邮件营销跟进。  
7. 需要出样：平面 / 3D / 包装 / 视频。  
8. 多电脑：数据最全端多次「同步全部资料」→ 另一端同步拉取。

## 8. 运行与部署要点（给运维向模型）

- 前端：Vite + React；可 Electron 桌面端。  
- 本机：IndexedDB / localStorage 存队列与草稿；云端（若已配置）做合并同步。  
- Admin：密钥池、数据接入、组织用户。  
- 挂机：保持业务页打开；夜间窗口跑重任务更合适。  
- 同步顺序策略：优先 CRM 与作业队列，大体量背调历史限额续传，避免单次超时拖死整库同步。

## 9. 给大模型的回答约束（生成对外材料时）

1. 用「外贸智慧协同」对外名；少堆技术黑话。  
2. 强调 **闭环与证据**，不要只吹「AI 自动找邮箱」。  
3. 竞品对比用能力维度，勿点名抹黑。  
4. 区分：已上线 / Coming Soon / 需配置密钥后可用。  
5. 前台演示文案遵守「无供应商商品名」原则。  
6. 数字（客户数、队列数）以界面口径为准：CRM ≠ 队列行数。

## 10. 一页纸摘要（可直接贴进 Prompt）

外贸智慧协同是出口团队的作业操作系统：在同一平台完成找客、批量背调、决策人（校验后邮箱）、产品匹配、CRM、开发信与产品出样（平面/3D/包装/视频）。设计强调任务流、证据驱动、组织权限与自有数据资产。相对 Hunter/Apollo/冷邮工具等「查邮箱或发信单点」，本平台优势是公司级作业闭环与产业带外贸场景，而不是单纯拼全球联系人库覆盖率。生态（认证/验厂/交付）为扩展位。Admin 可挂机补全；多端靠云同步合并。
