# 外贸智慧协同 · 安全强防范落地手册

> **读者**：平台负责人 / 运维（非业务员前台文案）  
> **目标**：防拖库、防盗刷上游额度、防接口爬取与白嫖、提高复刻成本  
> **诚实边界**：无法从技术上「保证产品形态不被仿」；能保证的是 **密钥与客户数据不轻易被拿走、算力不可被匿名刷爆**。  
> **关联文档**：`docs/并发扩容与规模化路线图.md`（容量）、`scripts/supabase-rls-harden.sql`（库隔离）、`api/_firewall.ts`（代理限流）  
> **更新日期**：2026-11

## 0. 怎么用这份手册 + 怎么让 Cursor 帮你

### 0.1 分工总表

| 谁 | 能做什么 | 不能做什么 |
|----|----------|------------|
| **你（控制台 / 账号）** | 开阿里云资源、买域名证书、Supabase 控制台跑 SQL、填密钥、改 DNS、安全组、WAF 规则、付款与实名 | 把账号密码发给聊天让 AI「远程登录控制台」 |
| **我（Cursor Agent）** | 改仓库代码、加 BFF/鉴权中间件、收紧前端不再直带 Key、写迁移脚本与检查清单、改 Electron 只打自家 API、提交/推送（你明确要求时） | 登录你的阿里云/Supabase/Vercel 控制台；替你保管生产密钥；在未授权时改生产 DNS |

### 0.2 推荐对话口令（复制到 Cursor）

按阶段执行时，直接发例如：

1. `按 docs/安全强防范落地手册.md 执行阶段 A：检查现网暴露面并列出待改文件清单`  
2. `按手册执行阶段 B：前端禁止直连上游 Key，统一走 /api 代理`  
3. `按手册执行阶段 C：补会话鉴权中间件草稿（先兼容现有登录）`  
4. `按手册写阿里云双机 Nginx 反代示例与安全组清单到 docs/`  
5. `按手册阶段 E：生产构建关闭 source map + 基础安全响应头`

**原则**：一次只做一个阶段；做完你验收，再开下一阶段。大改前先说「先出 Plan / 先 diff 范围」。

### 0.3 成功标准（有保证感的验收）

阶段全部做完后，应满足：

1. 浏览器 DevTools → Network：**看不到**完整上游供应商 API Key（最多看到你们自己的 session）。  
2. 用 anon / 公开密钥 **无法** 列出全库 CRM / 背调历史（RLS 或 Auth 挡住）。  
3. 未登录调用 `/api/qwen` 等 **被拒**（401/403）。  
4. 源站 ECS **不对公网开放**数据库端口；仅接入层/内网可访问业务 API。  
5. 异常高频请求在 WAF 或应用层被限流。

## 1. 现状风险（对照本仓库）

| 暴露点 | 现状 | 风险 |
|--------|------|------|
| 交付 | Vite 前端 + Vercel；Electron 加载线上站 | 整站 JS 可下载；桌面壳≠加固 |
| 上游调用 | 已有 `api/*` 代理与 `_firewall`，但浏览器侧仍可能持有/转发 Key | 抓包盗刷额度 |
| 数据 | Supabase + 本机 IndexedDB；RLS harden **曾故意跳过**（见 `SETUP-DONE-FOR-YOU.md`） | anon + 弱隔离时可拖业务数据 |
| 登录 | 前端校验密码哈希 + 用户表同步 | 权限可被改前端绕过展示层；真正读写若无服务端裁决则不稳 |
| 复刻 | 业务逻辑在前端包内 | UI/流程可被仿；数据与额度才是护城河 |

**结论**：迁阿里云、上双机 **值得做**；若不做「Key 出浏览器 + 强鉴权 + 库隔离」，只是换机房。

## 2. 目标架构（强防范版）

```
用户浏览器 / Electron
        │ HTTPS（仅 443）
        ▼
┌───────────────────────┐
│ 接入层（轻量 / SLB）   │  ← 公网唯一入口
│ · WAF / CC / 限流      │
│ · TLS 证书             │
│ · 静态前端（或 CDN）   │
│ · 反代 /api → 业务机   │
└───────────┬───────────┘
            │ 内网 / 安全组白名单（禁止公网直打业务机）
            ▼
┌───────────────────────┐
│ 业务层（ECS）          │
│ · 同源 BFF：/api/*     │
│ · 登录会话 / JWT 校验  │
│ · 上游 Key（环境变量） │
│ · 可选：背调 Worker    │
└───────────┬───────────┘
            │ 内网
            ▼
┌───────────────────────┐
│ 数据层                 │
│ · 云数据库（或收紧后的 │
│   Supabase / 自建 PG） │
│ · Redis（限流/会话）   │
│ · OSS（附件）          │
└───────────────────────┘
```

**双机职责切记**：

- **轻量机 = 门卫**（WAF、证书、反代、静态），不要放完整上游 Key、不要跑数据库。  
- **业务机 = 保险柜钥匙**（Key、会话、写库、调模型）。  
- **不要**两台都部署「同一套带 Key 的前端」。

## 3. 分阶段落地（一步步做）

总工期粗估（一人兼职）：阶段 A 0.5 天 → B 2–4 天 → C 3–7 天 → D 2–5 天（含云资源）→ E 1–2 天。可并行「你开云资源 / 我改代码」。

---

### 阶段 A — 盘点与止血（先做，成本最低）

#### A1. 你做：备份与权限盘点

1. 导出当前重要数据备份（CRM / 配置）：管理后台「同步」或 Supabase Table Editor 导出。  
2. 确认谁持有：Vercel、Supabase、GitHub、域名 DNS、各 AI/搜索供应商控制台。  
3. **轮换**仍怀疑泄露过的 Key（在供应商控制台作废旧 Key → 发新 Key）。  
4. 打开 Supabase → Authentication / Table Editor，确认当前 RLS 策略是否为 `USING (true)`。

#### A2. 你做：生成工作区密钥（若继续用 Supabase）

1. 本地生成长随机串（示例）：

```bash
openssl rand -hex 32
```

2. 把该串记到密码管理器（将作为 `WORKSPACE_ID`，**不要发到公开群**）。  
3. **先不要**对生产表直接改；等 A3 检查脚本与备份完成后再改。

#### A3. 我可做（你发口令）

口令：`按安全手册阶段 A：扫描前端仍直读 REACT_APP_* Key 的调用点，输出清单`

预期产出：一份「仍绕过 `/api` 的文件列表」+ 建议改造优先级。

#### A4. 你做：执行 RLS（高优先级止血）

> 曾跳过是为防误锁数据。现在按手册做 **必须先备份**。

1. Supabase SQL Editor：**先**把现有行的 `user_id` 统一改成你的 `WORKSPACE_ID`（脚本内有 UPDATE 示例，取消注释并替换）。  
2. 再执行 `scripts/supabase-rls-harden.sql`（把常量换成同一 ID）。  
3. 前端/环境配置相同 `VITE_WORKSPACE_ID`（构建与 Vercel/服务器环境变量一致）。  
4. 用另一浏览器无登录、仅 anon key 试读 CRM 表：应失败或空。

**验收**：匿名读不到业务表全量数据。

---

### 阶段 B — 密钥出浏览器（防盗刷，保证感最大的一步）

#### B1. 原则

- 浏览器 **只** 请求：`https://你的域名/api/...`  
- 上游 Key 只存在：Vercel Env / 业务 ECS 环境变量 / 阿里云 KMS。  
- 管理后台「保存配置」：改为保存到 **服务端保险柜**（加密表），不要把明文 Key 再下发到每个业务员浏览器（可下发「已配置/未配置」状态）。

#### B2. 仓库已有资产（复用，勿推倒重来）

| 路径 | 作用 |
|------|------|
| `api/qwen.ts` 等 | 上游代理 |
| `api/_firewall.ts` | 按 Key 指纹限流 |
| `scripts/aliyun-proxy-server.mjs` | 本机/自建反代参考 |
| `docs/并发扩容与规模化路线图.md` Phase 2 | 与本文一致的方向 |

#### B3. 我可做（你发口令）

口令：`按安全手册阶段 B：把 XXX 调用改为只走 /api，并确保响应不回传上游 Key`

建议拆单：

1. 先对话/背调主路径（qwen 类）  
2. 再检索类（tavily / anysearch / hunter）  
3. 再生图 / 3D / 邮件  

每合一类：`npm run typecheck` + 你在页面点一次真实功能验收。

#### B4. 你做：环境变量搬家

1. Vercel（过渡期）或阿里云业务机：配置 **仅服务端** 变量（不要加 `REACT_APP_` / `VITE_` 前缀到密钥上，避免打进前端包）。  
2. 从 `.env.local` / 管理后台逐步删除「打进前端的密钥」。  
3. 构建后打开 `dist/assets/*.js` 搜索 `sk-`：应搜不到生产 Key。

**验收**：Network 面板请求里 Authorization 指向你们自己的会话或空，由服务器注入上游 Key。

---

### 阶段 C — 服务端会话与接口鉴权（防破解白嫖）

#### C1. 目标行为

| 请求 | 未登录 | 已登录业务员 | 管理员 |
|------|--------|--------------|--------|
| 静态页面 | 可 | 可 | 可 |
| `/api/qwen` 等贵价接口 | 401 | 按配额 | 按配额 |
| 导出全量 CRM | 403 | 403 或仅本人 | 允许+审计 |
| 改组织/密钥配置 | 403 | 403 | 允许+审计 |

#### C2. 路径选择（二选一，推荐 1）

1. **Supabase Auth**（邮箱/密码或魔法链）+ 业务表挂 `auth.uid()` / `org_id`（长期正确）。  
2. **自建 JWT**：现有用户表迁到服务端校验密码，签发短期 JWT，`/api` 校验。

与现网「本机用户表 + 云同步」兼容时，可先做：**旧登录成功后换发服务端 session**，再逐步废弃纯前端验密。

#### C3. 我可做

口令示例：

- `按安全手册阶段 C：为 api/* 增加统一 requireSession 中间件，未带会话返回 401`  
- `按安全手册阶段 C：登录成功后改为请求 /api/auth/login 换 JWT，并写入 httpOnly Cookie（若部署允许）`

#### C4. 你做

1. 决定 Auth 方案（建议 Supabase Auth）。  
2. 全员通知：可能需要重新登录 / 改密。  
3. 验收：清 Cookie 后再调 `/api/qwen` 必须失败。

**验收**：改前端隐藏按钮无法调用贵价 API；必须有效会话。

---

### 阶段 D — 迁阿里云双机（防扫源站、国内可达、分层）

> 可与 B/C 并行准备资源；**切流量前**至少完成 A + B 主干。

#### D1. 你做：开通资源（控制台）

| 资源 | 规格建议（起步） | 用途 |
|------|------------------|------|
| 轻量应用服务器或 ECS + SLB | 2核4G 起 | 接入：Nginx、WAF、证书 |
| 业务 ECS | 4核8G 起（看队列） | Node BFF + 可选 Worker |
| 云数据库 RDS PostgreSQL（若离开 Supabase）或继续用 Supabase | 按量 | 数据 |
| Redis（可选） | 1G | 全局限流 / 会话 |
| OSS + CDN（可选） | — | 前端静态与附件 |
| WAF / DDoS 基础防护 | 按套餐 | 防 CC、常见爬虫特征 |

#### D2. 你做：网络与安全组

1. **业务机**：22 仅你的办公 IP；80/443 **不对公网**（或仅对轻量机内网 IP）。  
2. **轻量机**：开放 443（80 仅跳转 HTTPS）。  
3. **RDS**：仅 VPC；安全组只放行业务机。  
4. 轻量机 Nginx：`/` → 静态或反代；`/api/` → `http://业务机内网:端口`。

#### D3. 我可做

口令：

- `按安全手册阶段 D：生成 Nginx 反代样例、systemd 跑 Node、环境变量模板（不含真实密钥）`  
- `按安全手册阶段 D：把桌面端默认 origin 文档改为阿里云域名切换步骤`

产出到 `docs/ops/` 或本手册附录（由当次对话决定）。

#### D4. 你做：域名与切换

1. 备案（若用国内节点对大陆公网；否则可用海外地域，自行权衡）。  
2. DNS：`A` / `CNAME` 指到轻量/SLB。  
3. 先用测试子域（如 `app-staging.你的域名`）跑通登录与一次背调。  
4. 再切主域；Vercel 可保留一段时间作回滚。  
5. 桌面端：`resources/app-origin.txt` 或文档中的镜像地址改为新域（见 `desktop/README.md`）。

**验收**：外网 `nmap`/浏览器打不到业务机数据库端口；只经域名 443 进入。

### 阶段 E — 防爬与提高复刻成本（辅助层）

这些 **不能替代** A–C，只是加成本。

| 措施 | 你做 | 我可做 |
|------|------|--------|
| 阿里云 WAF 规则（扫描、频率） | 控制台配置 | 提供规则建议清单 |
| 登录失败锁定 / 验证码 | 选用服务（如滑动验证） | 接线到登录 API |
| 生产关闭 source map | 确认构建环境 | 改 `vite.config` 生产 `sourcemap: false` |
| 安全响应头 CSP / nosniff | CDN/Nginx | 提供 Nginx 片段与 `vercel.json` 头 |
| 导出带操作者水印 | 定规则 | 改导出 Excel/PDF 逻辑 |
| 审计日志（谁导出/谁改密） | 定保留周期 | 写 `audit_logs` 表与写入点 |
| JS 混淆 | 一般不优先 | 仅对极小核心可评估（收益有限） |

**验收**：无会话高频打 `/api` 被 429；构建产物无 source map。

### 阶段 F — 组织与运营（防内鬼与长期）

1. 管理员与业务员权限按现有角色模型执行；定期回收离职账号。  
2. 密钥 90 天轮换；供应商控制台开消费告警。  
3. 大客户数据：合同 NDA + 导出审批。  
4. 每季度用本手册「成功标准」做一次自测（可让我出检查脚本口令：`按安全手册出季度自检脚本`）。

## 4. 明确「没有保证」的部分

| 威胁 | 技术能否根治 | 现实对策 |
|------|--------------|----------|
| 同行做出类似外贸系统 | 否 | 数据资产、交付速度、行业服务、商标合同 |
| 已授权员工导出后外传 | 难根治 | 权限最小化、水印、审计、制度 |
| 合法会话被盗用（XSS/木马） | 降低 | CSP、httpOnly、短过期、设备绑定 |
| 开源/泄露本仓库 | 代码可被读 | 密钥永不进 Git；私有仓库 + 访问控制 |

## 5. 回滚与风险

| 动作 | 风险 | 回滚 |
|------|------|------|
| 执行 RLS harden | 配错 workspace 导致全员读不到云端 | 备份 SQL；临时恢复宽松策略（仅应急） |

| 切阿里云域名 | DNS 传播期打不开 | TTL 预先调低；Vercel 保留 |
| 强制 JWT | 旧 session 失效 | 提示重新登录 |

回滚经验亦可参考：`docs/ROLLBACK.md`。

## 7. 一页纸决策摘要

1. **先** 备份 + RLS/隔离 + Key 出浏览器。  
2. **再** 服务端会话挡 `/api`。  
3. **然后** 阿里云：轻量门卫 + 业务保险柜 + 库不进公网。  
4. **最后** WAF/混淆/水印等辅助。  
5. 复刻产品形态靠产品与数据，不靠藏 JS。  
6. 需要改代码时，用 **第 0.2 节口令** 分阶段叫我执行。
